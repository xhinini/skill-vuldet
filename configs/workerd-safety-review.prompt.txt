For every finding, include:

- A unique finding ID and title.
- `**Severity:**` Critical, High, Medium, Low, or Informational.
- `**Category:**` memory safety, lifetime/ownership, thread safety,
  concurrency, boundary safety, resource exhaustion, or another justified
  category.
- `**CWE:**` a CWE number only when it can be inferred confidently from the
  code; otherwise write `not confidently determined`.
- `**Location:**` exact repository-relative file path and line number.
- `**Affected function(s):**` the relevant function names.
- `**Vulnerable line(s):**` exact line numbers in the supplied snapshot.
- `**Exploit:**` a concrete attacker-controlled or unsafe concurrent sequence.
- `**Reachability:**` how the path can be reached and any required conditions.
- `**Impact:**` the security consequence.
- `**Evidence:**` the specific code behavior that establishes the finding.
- `**Remediation:**` a specific corrective action.
- `**Confidence:**` High only for findings reported in this benchmark.

Do not report style issues, mere hardening opportunities, unchecked patterns
without a demonstrated impact, or hypothetical concerns. If no vulnerability
